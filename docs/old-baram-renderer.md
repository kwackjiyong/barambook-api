# 옛날바람 서버 렌더러

`src/assets/dat/old-baram.obp` 한 파일을 API 서버 시작 시 메모리에 올리고,
요청된 파츠와 동작을 합성해 투명 PNG로 반환한다.

## 선택 목록

```http
GET /renderer/old-baram/options
```

머리, 갑옷, 무기, 방패의 ID와 사용 가능한 염색 번호, 동작 및 방향 목록을
JSON으로 반환한다.

## 염색 목록

```http
GET /renderer/old-baram/dyes?slot=head&head=0&body=20&weapon=-1&shield=-1&direction=1
```

`slot`(`head`/`body`/`weapon`/`shield`)이 가리키는 부위의 염색을 전부
같은 크기의 썸네일로 그려 한 응답에 담는다. 나머지 쿼리는 PNG 렌더링과 같고,
자세는 서기, 그림자는 꺼진 채로 고정된다.

```json
{ "slot": "head", "item": 0, "zoom": 2, "width": 38, "height": 82,
  "dyes": [{ "dye": 0, "image": "<base64 PNG>" }] }
```

염색 하나에 요청 한 번씩 왕복하지 않도록 목록 팝업이 이 엔드포인트를 한 번만 부른다.

## 부위 선택 목록 시트

```sh
npx ts-node -T tools/build-old-baram-part-sheets.ts
```

부위별로 모든 아이템의 기본샷을 격자 PNG 한 장에 구워 `cdn-upload/` 에 쌓고,
S3 업로드 명령을 출력한다. 아이템이 수백 개라 API로 한 장씩 그리는 대신
CDN에 미리 올려 두고 프론트가 칸만 잘라 쓴다. 칸마다 워터마크가 함께 찍힌다.

폴더 이름에는 **결과물 자체의 해시**가 들어간다(통파일이 아니라). 렌더 코드가 바뀌어
그림이 달라져도 번호가 그대로면 immutable 로 올라간 옛 시트가 영영 남기 때문이다.
업로드 뒤 프론트 `src/app/old-render/partSheets.ts` 의 판 번호를 함께 바꾼다.

## PNG 렌더링

```http
GET /renderer/old-baram?head=0&headDye=0&body=20&bodyDye=0&weapon=1&weaponDye=0&shield=0&shieldDye=0&state=attack&direction=1&frame=0&zoom=4
```

응답의 `Content-Type`은 `image/png`이다.

| 쿼리 | 기본값 | 설명 |
| --- | ---: | --- |
| `head`, `headDye` | 첫 머리, `0` | 머리와 염색 |
| `body`, `bodyDye` | 첫 갑옷, `0` | 갑옷과 염색 |
| `weapon`, `weaponDye` | `-1`, `0` | 무기와 염색. `-1`은 맨손 |
| `shield`, `shieldDye` | `-1`, `0` | 방패와 염색. `-1`은 없음 |
| `state` | `stand` | `stand`, `move`, `attack`, `cast`, `pickup`, `eat`, `die`, `emote` |
| `direction` | `1` | 남 `1`, 북 `2`, 서 `4`, 동 `8` |
| `frame` | `0` | 동작 프레임 |
| `emote` | `0` | 감정표현 번호 `0~15`. 15번은 12번과 같은 그림이라 선택 목록에서는 빠진다 |
| `colorFrame` | `0` | 색상 애니메이션 프레임 `0~7` |
| `shadow` | `true` | 그림자 표시 여부 |
| `zoom` | `4` | 최근접 확대 배율 `1~4`. 의상실 미리보기가 340px로 묶여 있어 더 키워도 화면에서는 줄어든다 |

## 워터마크

모든 렌더 결과에 출처를 찍는다. 끌 수 있는 경로는 없다.

**무대 바탕색(`#efe8d9`)** 글자를 세로로 4줄 반복해 얹는다. 한 줄에 두 겹이다.

- **캐릭터 뒤**: 불투명하게 깐다. 캐릭터가 가린 자리는 덮이고 빈 여백에만 남는다.
- **캐릭터 위**: 같은 자리에 낮은 알파로 얹는다.

의상실 화면에서는 바탕과 같은 색이라 눈에 잘 안 띄지만, 내려받아 다른 바탕에 올리면
드러난다. 글자가 캐릭터를 가로질러 지나가고 줄이 여러 개라 잘라낼 수 없다.

프론트가 무대·부위 썸네일·목록 타일에 모두 같은 색을 쓴다. 바탕색을 바꾸면
`INK` 값도 같이 바꿔야 한다. 진하기는 `INK_ALPHA` 하나로 조절한다.

- **크기**: 그림 폭의 `TARGET_WIDTH_RATIO`(0.62)만큼. 확대가 끝난 그림에 1픽셀로 찍거나
  정수 배율로만 키우면 확대율이 바뀔 때마다 크기가 튄다. 배율을 소수로 두고 글자 칸을
  사각형으로 채워 어느 확대율에서나 같은 비율로 보이게 한다.
- **자리**: 캔버스 바닥이 아니라 **그려진 화소**의 바닥에 맞춘다. 캔버스는 모든 자세를
  담느라 여백이 넓어서, 바닥에 맞추면 캐릭터에서 한참 떨어진 빈 곳에 놓인다.

## 핫링크 차단

Origin/Referer 가 있는데 우리 도메인이 아니면 `403` 을 준다. 허용 도메인은
`ALLOWED_ORIGIN_HOSTS` 로 바꾼다(기본 `barambook.com,www.barambook.com,localhost,127.0.0.1`,
서브도메인 포함).

헤더가 아예 없는 요청은 통과시킨다. 이미지 주소를 새 탭에서 바로 열거나 메신저가
링크 미리보기를 가져갈 때 헤더가 붙지 않아, 막으면 공유가 깨진다. 헤더를 지우고 긁는
수집기까지 잡자는 것이 아니라 퍼가서 자기 화면에 띄우는 쪽을 끊는 것이 목적이다.

## 속도 제한

합성 한 장이 서버 CPU를 약 10ms 쓰고 프로세스가 하나뿐이라, 막지 않으면 전량 수집이
두어 시간이면 끝나면서 그동안 서버가 통째로 눌린다. IP당 토큰 버킷으로 묶는다.

| 엔드포인트 | 상시 | burst | 근거 |
| --- | ---: | ---: | --- |
| `/renderer/old-baram` | 초당 10회 | 30 | 정상 사용 최대치가 동작 재생(초당 5장)이라 그 두 배 |
| `/renderer/old-baram/dyes` | 2초당 1회 | 6 | 한 번에 32장을 그려 렌더의 32배를 쓴다 |

넘으면 `429` 와 `Retry-After` 를 준다.

클라이언트 주소는 X-Forwarded-For의 **뒤쪽**(신뢰하는 프록시가 덧붙인 값)에서 읽는다.
`main.ts` 가 `trust proxy` 를 켜 두어 `req.ip` 는 맨 앞 값인데 그 자리는 클라이언트가
직접 써 보낼 수 있어, 그대로 쓰면 헤더만 바꿔 가며 제한을 피할 수 있다.
프록시가 둘 이상 겹쳐 있으면 `TRUSTED_PROXY_HOPS` 환경 변수로 개수를 알려 준다(기본 1).

같은 파라미터의 PNG는 프로세스 메모리에 최대 512개까지 캐시한다.
통파일 위치는 기본적으로 `src/assets/dat/old-baram.obp`이며,
필요하면 `OLD_BARAM_OBP_PATH` 환경 변수로 변경할 수 있다.
